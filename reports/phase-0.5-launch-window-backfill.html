Schema · migration 0002

Three-way row split

historical_releases separates API-derived fields, curated research, and provenance. Re-running the backfill refreshes the machine half and never overwrites research. release_windows stores metrics per named window instead of one lifetime snapshot.

Pipeline · jobs/

Idempotent backfill

backfill_historical.py reads the curated CSV, fetches four Steam requests per game, and upserts. The loader rejects a label with no research behind it — and research with no label — so nothing uncited reaches ground truth.

Dataset · data/

126 releases, 2015–2025

Every row carries full API data. 12 carry the seed batch's labels and sources; 114 await the Phase 1 research pass. Only rows with a resolved outcome are eligible for training.

Correction

The spec was wrong about what Steam remembers

The spec assumed windowed review figures could not be recovered for past releases, and that historical rows would have to lean on whatever numbers press coverage happened to report. Testing against the live API showed otherwise: appreviews accepts start_date/end_date with date_range_type=include, and returns counts aggregated over just that window — one request per game per window, no pagination.

That section of PROJECT_SPEC.md is corrected in place. It is not a footnote-sized difference.

Finding

Sentiment doesn’t separate outcomes. Volume does.

With launch-window data in hand, the labeled set says something the rubric should absorb before Phase 1 starts. Helldivers 2 — a breakout — and Suicide Squad: Kill the Justice League — a flop — have identical two-week positive review shares. What separates them is that one drew 24× the reviews.

What this implies for the rubric

Review share is close to useless on its own at the launch window — Concord, the clearest flop in the set, sits at 65.8% positive, above Forspoken and far above Redfall’s 27.2%. Review count, normalised within a release-year cohort, is doing the separating work.

That matches what the spec already anticipated under Cohort Normalization, and it argues for defining the Success and Breakout thresholds in cohort-relative terms from the start rather than as absolute numbers.

Traps

Three ways this data lies

Each of these produces a number that looks entirely valid. All three are handled in the backfill; the first surfaced as a live bug in the first full run.

Handled · skipped with a warning

Windows that haven’t elapsed

A three-month window on a title released three weeks ago returns a real count covering the wrong period, and nothing downstream would notice. Those windows are now skipped rather than stored.

Handled · flagged in the CSV

Early Access dates

Steam reports the 1.0 date, not the Early Access launch — Palworld reads as a 2026 release. Any EA title needs a curated original_release_date before its windows describe the right event.

Handled · curated field

Price drift

price_overview.initial is today’s list price, not the launch price. The Witcher 3 launched at $59.99 and lists at $39.99. Launch price is curated; the API value is kept separately.

Known gaps

  • Labels114 of 126 rows are unlabeled. Deliberate: no sourced research exists for them, and inventing citations would poison the training set. The spec’s Phase 1 is the labeling pass, and it now has a ready worklist with the expensive API half already done.
  • Critic scoresPresent for 72 of 126. Steam’s Metacritic field is patchy and absent for most of the labeled games, including Concord, Redfall and Black Myth: Wukong. OpenCritic is the next data source to add.
  • Concurrent playersNot recoverable, permanently. Steam publishes only a live count and SteamDB scraping is off the table, so peak_concurrent_players stays null on historical rows rather than borrowing a present-day reading.
  • Missing gameBabylon’s Fall is omitted. It is delisted, so store search cannot surface it, and GetAppList now requires a Steam Web API key — the first concrete thing that key would buy.
  • Launch typeUnknown for 114 rows. platform_launch_type derives from the gap between Steam and true first release, so it stays unknown until original_release_date is researched. The 12 labeled rows resolve correctly, including two delayed ports and one former console exclusive.
